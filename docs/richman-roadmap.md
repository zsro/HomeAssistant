## 关键决策

- **先存档，后联机，但共同设计协议。** 存档解决状态完整性、版本和恢复；联机复用这些基础，把实时裁决移到服务端。
- **单机云存档与联机对局分开。** 单机存档允许本人回退进度；联机由服务器持有唯一历史，房主不能用个人 LOAD 覆盖其他玩家进度。首版不将个人存档转换为联机房间。
- **服务端权威。** 客户端提交意图，不提交最终资金、骰子结果、胜者或“动画已完成”。当前 `expectedRevision` 和 `decisionId` 是基础，不是完整网络安全协议。
- **不先扩地图。** 在现有日本地图验证最复杂的债务、拍卖、非当前回合反应、时光机、科研与小游戏，再复制到新内容。
- **规则与版本保持稳定。** 迁移宿主不擅改 v47 或历史回放；确需改变规则时新增版本，保留旧指纹与旧档处理策略。

## 下一任务：联机发布验收

NET-03 已补齐持久待确认意图、回执与投影原子核对、自动重连、原地登录恢复、旧控制 ID 退役和进程重启接续；[恢复验收](richman/net-03-results.json)。2/3/4 人及人机覆盖的是创建/准备/开始/恢复矩阵，尚不代表每种人数均已完成复杂资产长局。HTTP 轮询继续用于正式客户端，暂不需要 WebSocket。

1. 补多人完整长局与混合 AI 实际轮次；在独立客户端中组合债务、拍卖、反应、公司、时光机和科研，不用恢复矩阵替代资产链条验收。
2. 补公网延迟、真实移动设备和并发负载测量；32 个活动局只是准入上限，未承诺此规模的实时性能。网络事件流/逐动作音效另立安全投影，不由当前状态猜测历史演出。
3. 长期离线保留并等待本人，不自动托管/删除；结束局保持可读，活动局满额拒绝创建。将来若要归档、自动超时或共同暂停，需要明确用户操作和独立协议，不能借清理容量删除存档。
4. 准备发布环境验收：生产迁移备份、存档大请求 Nginx 配置、端到端认证与联机恢复。生产发布须另行执行；本次只完成本地实现和云测试库验收。

发布仍独立执行：本地正式打包、Git 提交/推送、服务器干净且 HEAD 同步后部署；生产迁移前备份，并验证存档专用 Nginx 配置和公网大档。本次未提交、未部署。
