## 1. Goal — 目标

将用户提供的《大富翁 4》本体素材接入 HomeAssistant 模块集合，逐步完成可在浏览器运行、规则与表现高度接近原版的游戏。先让日本地图可以完整对局，再补齐策略系统、电脑对手、声音和其他地图。

“高度完整”以规则清单、内容清单和可复现的原版对照结果为验收依据，不以页面看起来相似或单局能够运行替代。原版未核实的行为必须标注，不能悄悄用自创规则填补。

## 3. Core Gameplay — 目标玩法

新建对局 → 选择地图、角色与控制方式 → 按原版规则初始化资产 → 当前玩家处理回合开始效果 → 执行允许的回合操作 → 掷骰 → 行走及经过事件 → 落点结算 → 处理债务或破产 → 检查结束条件 → 下一玩家。

S1 先支持日本地图与本地人类轮流操作，现金、存款、地产与建筑作为核心资产。破产及胜负条件以核验结果为准；暂定的实现规则必须进入规则登记表并向体验者说明。S3 再加入使用相同合法操作接口的 AI。

暂停保留当前状态；重新开始需确认并建立新对局；S4 提供账号存档与继续游戏。刷新丢失进度的提示在存档落地前保留。

| 区域 | 计划内容 | 阶段 |
|---|---|---|
| 对局入口 | 新建对局、地图、角色、人数与初始配置；后续增加读档 | S1 / S3 / S4 |

## 5. Interaction Flow — 实施后的操作流程

1. 登录进入游戏，缺少素材时提供明确错误和重试；已有存档时显示“继续游戏”。
2. 新建对局并验证配置，加载指定地图和角色后进入首个玩家回合。
3. 根据当前阶段开放合法操作。选择道具目标可取消；非法目标不能扣减道具或资产。
4. 掷骰后锁定结果，动画展示已确定的移动；岔路等待选择，经过事件按规则中断或继续。
5. 落点显示对应决策，确认后只结算一次，关闭或重复点击不能再次扣费。
6. 处理付款、债务、退出对局与结束条件；未结束则轮换到下一有效玩家。
7. 随时可暂停。支持存档后，在已定义的稳定决策点保存；载入需恢复玩家、资产、待选操作与随机状态。
8. 结束后展示结果，允许新开一局或返回模块集合；离开页面释放游戏资源。

## 6. States And Feedback — 状态与反馈

以下是目标状态设计。S1-02～S1-04 已实现加载、移动、岔路、暂停、地产、基础存取款、债务确认、破产退出及最后存活者胜负；其他胜负模式、贷款/利息/拍卖与存档仍待实现。

| 状态 | 用户反馈与行为 |
|---|---|
| 加载 / 失败 | 资源进度、失败原因、重新加载；禁止开局 |
| 开局配置 | 未满足人数或角色条件时禁用开始，指出缺失项 |
| 回合开始 / 等待操作 | 高亮当前玩家；仅允许该玩家的合法命令 |
| 掷骰 / 移动 | 展示点数与剩余步数，禁止重复掷骰和切换操作者 |
| 岔路 / 目标选择 | 高亮合法选择，取消策略由对应规则确定 |
| 落点决策 / 事件结算 | 显示价格、余额与结果；提交后禁用重复确认 |
| 债务处理 / 破产 | 清晰列出待付金额和允许的处理方式；结算完成后再轮换 |
| 暂停 | 暂停动画、AI 和规则推进；恢复到原决策位置 |
| 对局结束 | 禁用改变对局的命令，展示胜者及结束原因 |
| 保存 / 保存失败 | 明确成功时间；失败保留当前对局，可重试，不能假装保存成功 |

全屏是显示状态，不改变回合、骰子或资产。切换窗口尺寸和退出全屏不能触发游戏重新初始化。

### 必须覆盖的边界

- 路过与停留是否分别触发；强制转移后能否继续走；单向道路和连续岔路。
- 精确余额、余额不足、付款后破产、地产转移、最后一位玩家及平局条件。
- 同一位置多玩家、人物和建筑遮挡、升级后建筑锚点变化。
- 道具目标已失效、连续效果、状态到期、玩家离场、卡片取消及背包边界。
- 重复点击、过期回调、确认弹窗中暂停、后台恢复、退出中途加载。
- AI 思考中暂停、重置、读档或离开页面，旧任务不得修改新对局。
- 存档缺失素材、版本不兼容、账号过期、网络失败、多标签覆盖同一存档。
