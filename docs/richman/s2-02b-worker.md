## 实现与兼容

默认新场景改为“建造对局（机器工人限定版）”，新规则 `japan-tools-candidate-v2`。新建界面保留“道具对局（遥控骰子，候选规则）”对应 v1，以及地产、仅移动和自由验证。新 profile 的指纹含首批指纹、工人参数与完整效果 registry。

`construction.ts` 独立保存 v2 参数/注册表/目标校验，items.ts 的 v1 参数与指纹不改。旧三种早期规则及 v1 共四种历史规则仍可回放；状态/回放容器保持 v1。追加 `propertyBuilt` 事件记录地产 ID、前后等级和原所有者；消费和建造只由 GameEngine 一次提交。

前端显示工人数量、禁用原因、当前地产的路格/归属/等级以及确认/取消，建造结果直接更新原住宅显示。没有测试状态注入、素材修改、数据库/鉴权/依赖变更。

## 失败原因与下一步

转向卡阻塞点从“底层方向未读”收敛到“+14 字段与 Web previous 的对应、禁行位、岔路随机选择和可选对象命中范围”，源码位置已记录。机器工人远处选地阻塞在原版 440×440 命中图层、视窗变换和遮挡顺序，不能把屏幕像素直接当世界距离；未尝试把未知范围硬编码为全图或邻接若干格。

**下一批优先 S2-02 第三批：补齐目标选择证据**。先沿本报告的 selector/hit-test/方向入口追完可选范围，决定扩展工人还是接转向卡；卡片首次启用前仍需初始/随机获取、15 格卡包、共享卡池。若扩展本轮范围或改变满级规则，新增 v3 并保留 v1/v2 registry/指纹，不能改旧 profile 让回放失效。路障可作为后续候选，但先核验放置限制、占位与移除后的供应回补，不凭名称接入。
