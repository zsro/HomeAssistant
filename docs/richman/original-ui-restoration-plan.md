# 《大富翁4》原版 UI 还原实施计划

日期：2026-10-19。代码基线：`817abba`。状态：**UI-00～UI-08 本计划必做范围已完成，本地发布包已校验**；原版风格 UI、入口及适配已验证，仍有单列视觉/业务差异，不代表原版 100% 复原；尚未部署。

## 1. Goal · 目标

将现有大富翁 Web 页面改造成以原版《大富翁4》为参考的游戏界面：地图是主体，顶部使用原版工具栏，右侧展示人物与资产，下方提供小地图/日期视图，游戏决策在场景内弹出对应窗口。优先使用已经确认的原版素材，保留现有游戏规则、电脑玩家、回放和地图交互。

**2026-10-18 用户确认：接下来核心是复原 UI。** 尚未实现的功能保留原版入口、图标和布局位置，实际业务暂时挂起，不因业务缺失隐藏入口或阻塞界面复原。点击此类入口时显示“功能暂未接入”等明确提示；有已核实窗口素材时可先还原窗口外观，业务操作保持不可执行。已有可用功能继续接入原有逻辑。

分两级验收：**主体完成**指原版主布局与已有核心操作可用；**本计划必做范围完成**还须覆盖当前 Web 已支持的业务窗口、开始/结束流程及移动端，并保留未实现功能的原版入口。分别记录“UI 还原状态”和“业务接入状态”：业务挂起不阻塞对应 UI 验收，但不能计为功能已实现。复杂原版演出可按既有约定暂缓；尚有视觉缺项时不能宣称“全部原版 UI 已 100% 还原”。

UI-00 已交付 [资源审计](original-ui-resource-audit.md)、[机器清单](original-ui-resource-audit.json) 和 [联系表](ui00/README.md)。UI-01 已交付 [主界面骨架、截图与验证记录](ui01-main-shell.md)；UI-02 已交付 [人物资料、GO、多骰、日历与小地图](ui02-turn-information.md)；UI-03 已交付 [工具入口、统一窗口、焦点与防重入](ui03-window-host.md)；UI-04 已交付 [地产、目标选择与基础银行窗口](ui04-property-bank.md)；UI-05 已交付 [库存与经营窗口、原图证据及暂缓清单](ui05-inventory-business.md)；UI-06 已交付 [事件与应答窗口、原图和嵌套验证](ui06-events-responses.md)；UI-07 已交付 [菜单、设置与多尺寸适配](ui07-menus-responsive.md)。UI-08 已交付 [总验收与发布准备](ui08-acceptance-release.md)、[暂缓清单](ui08-deferred.md) 和 191 文件正式发布包，打包校验通过；未提交、推送或部署。

## 3. Core Gameplay · 保留的游戏闭环

进入游戏 → 选择新局/已有支持的继续方式 → 配置人物与电脑 → 查看当前人物 → 使用道具或掷骰 → 沿路线移动/选择岔路 → 处理落点及嵌套决策 → 下一位 → 破产退出或产生胜者 → 查看结果/重新开始。

新 UI 只改变入口和呈现方式。移动、费用、库存、日期、骰子随机数和胜负仍由 `GameSession`/引擎决定。所有确认操作调用现有命令，传入当前决策 ID；展示组件不得自行扣款、结束回合或推进动画完成事件。

电脑回合显示当前应答者和执行状态，禁止替电脑提交操作。进入银行、拍卖或反应时，窗口标识实际应答玩家，不能默认使用正在移动的角色。

以 **640×480** 为逻辑画布制定布局。下表四个主区域已由 UI-00 核对本地程序的绘制矩形；内部字段、部分状态和遮挡关系按审计未知项继续核实。

| `NewsPanel`、`FortunePanel`、拍卖/反应/处置 | 事件或应答弹窗 | 支持决策链和应答人改变，禁止重复提交 |

所有支持功能都必须登记“旧入口 → 新入口 → UI 还原状态 → 业务接入状态 → 验收用例”，无入口的功能视为迁移遗漏。原版尚未实现的功能同样登记入口，业务状态设为“挂起”，附原因和恢复条件；入口与界面可先独立完成。

### 4.3 响应式策略

- 桌面和足够大的横屏：保持 4:3 逻辑画布，等比放大，空余区域留边；地图不裁切、不变形。
- 紧凑横屏：沿用原版区域关系；工具栏提供点按名称提示，关键操作热区尽量达到 44×44 CSS 像素。空间不足时用工具抽屉代替重叠热区。
- 手机竖屏：采用 Web 适配布局，地图占主要宽度，人物资料压缩为信息条，业务窗口变为抽屉或全屏面板；不把整套 640×480 硬缩到文字不可读。该模式不以像素级原版一致作为验收条件。
- 改变尺寸、旋转屏幕、进入/退出全屏时保持同一对局、同一待处理决策和输入状态。

## 5. Interaction Flow · 交互流程

1. **加载**：显示原版风格加载层；必要资源加载完毕后启用开始操作。失败提供重试，当前可恢复的对局不能被自动重置。
2. **开始菜单**：START 打开现有开局设置，OPTION 打开声音/显示/操作设置；返回站点和退出当前对局分开。未实现的 LOAD 保留原版入口和图标，点击说明业务暂挂，不执行读取或显示成功反馈。
3. **开局**：普通设置展示人物、控制方式、资金等必要选项；候选版本、种子、验证模式移到高级设置，旧模式和回放兼容入口保留。
4. **正常回合**：右侧跟随当前人物；工具栏打开对应窗口；GO 根据状态显示掷骰、等待或下一位。窗口按钮状态来自现有规则。
5. **地图目标选择**：打开卡片/道具 → 选择物品 → 窗口收起至提示条 → 地图或列表选目标 → 显示预览 → 明确确认 → 调用现有命令。拖动、缩放、右键和空地点击不提交操作。
6. **落点决策**：自动打开当前必须处理的窗口并转移焦点；确认后进入下一真实决策或回到地图。银行、拍卖、反应、破产等嵌套流程不能被通用关闭按钮跳过。
7. **浏览窗口**：关闭只结束浏览，不执行游戏命令。是否允许某项交易由现有校验决定；不会通过“打开设置”隐式改变规则时钟。
8. **暂停/重开/退出**：暂停使用现有暂停命令；继续恢复当前窗口。重开与退出先确认，取消后恢复之前的暂停状态和焦点，不自动继续原本已暂停的游戏。
9. **结束**：停止可改变对局的工具操作，展示胜者、结果与新局/回放入口。结果窗口不冒充尚未移植的原版结局动画。

## 6. States And Feedback · 状态反馈

| 状态 | 可见反馈 | 操作约束 |
| --- | --- | --- |
| 加载中/资源失败 | 进度或具体失败提示、重试按钮 | GO 与交易禁用，不显示空白可点图标 |
| 等待掷骰 | 当前人物、骰数、GO 正常态 | 按合法性开放物品及业务入口 |
| 掷骰/移动 | 骰子动画、剩余步数 | 禁止重复掷骰与影响当前行动的指令 |
| 岔路/目标选择 | 高亮候选与文字列表、确认/取消语义 | 只允许当前决策的合法目标 |
| 业务应答 | 原版风格窗口、应答人、费用/数量、确认态 | 提交后立即防重入；过期决策重绘 |
| 电脑执行 | 电脑行动提示 | 人类不能抢答；暂停和已有重试入口可用 |
| 暂停 | 明确遮罩、继续按钮 | 停止动画、小游戏计时和电脑动作；不隐藏正在处理的问题 |
| 空库存/资金不足/无目标 | 原版背景上的文字解释 | 禁用并说明原因，不能仅靠灰色表达 |
| 破产/已离场/对局结束 | 对应人物状态及结算窗口 | 不允许已离场角色继续操作 |
| 可选皮肤缺失 | 同一窗口使用 Web 文字/基础边框回退 | 当前决策仍可完成；完整性验收记录为缺项 |
| 业务尚未实现 | 保留原版入口，点击显示未接入提示或已还原的窗口外观 | 业务操作暂挂，不修改对局，不伪造成功；UI 与业务状态分别验收 |

按钮至少定义正常、悬停、按下、选中、禁用五类 Web 状态。只有已确认的原图帧才能标为原版状态；键盘焦点框属于必要的 Web 增补。关键金额和确认文本保留可访问的 DOM 文本，不烘焙进图片。

## 7. Rules And Edge Cases · 规则与边界

- 当前真正待处理的决策优先于普通浏览窗口；不以单个 `phase` 字段猜测全部情况，包含保险等独立 decision 字段。复用并扩展 `decision-navigation.ts` 的判定。
- 一次只挂载一个可提交的当前决策组件，避免桌面/手机两套隐藏表单同时运行副作用或提交相同命令。
- Escape：先关闭可关闭的浏览/预览，再处理原生全屏；不能关闭必须应答窗口而使对局失去入口。取消行为必须对应已有命令。
- 地图缩放、画布缩放、DOM 覆盖层和设备像素比使用一致的坐标换算；不能给 Pixi 与 HTML 分别添加互不对应的缩放。
- 小地图只改变相机，不瞬移玩家、不改变节点。禁用调试瞬移入口在正常模式下的误触。
- 金额较大、长名字、多状态徽章及繁简体字形均需覆盖；金额不能因省略号而失去关键位数，明细可查看完整值。
- 原 UI 的持卡姿态、完整特效和口型若无已确认触发条件，列为暂缓；不能用随机动画表达业务结果。
- 存读档需独立的数据版本、恢复合法性及完整回放验证；回放下载不是存档，原生 `.sav` 兼容不纳入本轮。LOAD 暂缓时说明原因，不能以“UI 已有图标”计为功能完成。
- 暂缓单必须包含：项目、证据、阻塞点、保留方案、恢复条件、影响的验收项。优先推进不受阻塞的其他窗口。

### 8.2 代码组织建议

| 拟新增模块 | 职责 |
| --- | --- |
| `ClassicGameShell` / `classic-ui.css` | 逻辑画布、布局模式、外层缩放和主题 |
| `ClassicToolbar` | 图标、名称、快捷键提示、可用性与原有入口绑定 |
| `ClassicPlayerPanel` / `ClassicMiniMap` | 只读资料与相机导航，不另算一套经济规则 |

| `ClassicMenu` | 开始、设置、开局、结果流程及暂缓项状态 |
| `ui-presentation.ts` / `ui-art.ts` | 快照到展示数据的纯函数、资源映射与校验 |

名称为建议，实际拆分服从现有组件边界。`RichmanPage.tsx` 留作场景生命周期与组合入口，避免继续加入大量条件 JSX。先给现有业务组件套原版外框，再逐窗调整内部布局，原命令回调和合法性校验继续复用。

窗口层 UI 状态只保存打开的浏览页、选中标签、输入草稿和焦点恢复对象；必须处理的窗口由最新快照推导。`decisionId`/游戏 ID 变化时清理过期草稿，重开时统一清理窗口状态。

### 8.3 验证门槛

- **视觉**：冻结 640×480 基准截图，检查主区域边界、图标顺序、字体/边框和留白；用相同地图/人物/决策状态做对照。资源组合图与真实运行截图分别标注，不能混作证据。
- **窗口覆盖**：登记当前全部可达决策及嵌套路径，每项都有可访问的新入口和至少一个浏览器场景。无原图的回退窗口保留功能，但不能在视觉覆盖表中标成原版完成。
- **行为**：覆盖正常掷骰、车辆多骰、岔路、地图选目标、买地/升级/租金、银行、库存/卡片、股票、商店、事件链、拍卖/反应、破产/认输、小游戏及电脑回合。
- **数据**：相同种子与同一业务命令序列，比较规则状态、资金、库存、事件与 RNG；排除测试专用 UI 操作，但不得过滤真实规则差异。既有回放矩阵继续通过。
- **尺寸**：至少检查 640×480、1280×960、1440×900、844×390 和 390×844；覆盖高 DPI、全屏切换、窗口缩放与手机旋转。
- **可操作性**：键盘可到达主要入口和确认按钮；对话框有标题、焦点约束和关闭后的焦点恢复。触屏不依赖悬停，地图拖动不误提交。
- **异常/生命周期**：缺图、加载重试、暂停、重复点击、过期决策、重开和离开路由；退出后无残留 canvas、RAF、监听器与业务窗口。
- **资源**：无运行资源 404；按需加载大窗口；纹理预算沿用不超过 4096×4096；使用同一设备记录改造前后的首屏加载和帧率，出现明显退化先定位再验收。

复用现有 `map-picking-ui-browser.cjs`、`map-art-browser.cjs`、`presentation-art-browser.cjs`、各业务浏览器脚本与回放测试。为主布局、窗口切换和新增资源校验补充有实际风险覆盖的测试，不为每个 CSS 属性编写镜像测试。
