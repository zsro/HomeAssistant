# S1-05：日本地图对局验收

日期：2026-10-02。验收范围是 `japan-finance-candidate-v1` 的本地 2–4 人普通地产完整对局；不代表原版所有玩法或行为一致性已经完成。

## 方法与可复现入口

- 引擎：`frontend/src/features/richman/game/acceptance.test.ts`，原始 110 节点 fixture、真实地产目录，2/3/4 人各一局。种子 `s1-04-loop`，每人 30,000，能负担即买地/升级，银行取出全部存款，岔路选择 `(turn - 1) % choices.length`。
- 浏览器：`scripts/richman/acceptance-browser.cjs`，本地 Vite + Chrome；原始 manifest、道路、素材均不改写。双人选择孙小美/钱夫人，三人选择前三位，四人全选。
- 长局只在隔离浏览器中包装 `GameSession.tick`，每帧重复调用原始 50ms tick，直到下一个待决策点。动画确认仍由适配器发送并经过引擎验证；所有掷骰、岔路、购买、升级、租金、银行、债务、轮换均激活页面上已启用的按钮，不直接调用模型决策方法；长局不逐次模拟鼠标移动和滚动。没有注入资金、位置、地产、骰子结果或终局状态；产品中没有加速开关或测试入口。
- 独立引擎预先生成合法操作计划；每回合与债务时比较页面当前角色、破产人数、全部余额和轮数/回合。最终下载实际页面回放，比较完整状态及事件（仅归一化随机 gameId、token 中的 gameId 前缀与命令标签），避免把计划自身误当浏览器结果。
- 长局加速不验收原速每一帧。另跑正常速度交互回归，覆盖暂停、旧模式、重开、全屏、窄屏与资源释放。
- 鉴权仅由测试 BrowserContext 模拟；应用登录和云端 MySQL 没有变更，测试不请求生产数据。

引擎三局已通过以下断言：

1. 从初始余额另建账本，只按成功事件记账；每个命令后与引擎的全部现金/存款比较，整数且非负。租金/债务入账对方存款；银行只搬移资金；买地/升级扣款可追溯。
2. 银行、地产、清算命令重复提交均拒绝，状态不变。
3. 破产释放地产归属，保留等级；任何破产玩家不再拥有地产。四人长局中已建地产再次按地价加建造成本购入，等级不变。
4. 中间淘汰后按原阵容跳过破产者，轮数只在绕回阵容前部时增长。三人及四人局均存在淘汰后继续轮换。
5. 四人长局覆盖银行经过和落点；全部对局只有一次终局事件和唯一存活者；终局不能继续轮换。
6. 全量回放重建状态和事件完全一致。
