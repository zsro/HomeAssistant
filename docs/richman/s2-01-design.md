# S2-01 效果框架设计

## Goal

为后续卡片、道具和事件提供带证据的目录及可确定性重放的效果状态转换，保留 S1 的完整对局。此次交付开发基础，不开放尚未核验的游戏操作。

## Scope

- 本轮：30 卡、13 道具、商店和事件入口目录；原文件/源码证据；选择、确认、取消、库存消耗、持续效果、冲突、到期与目标失效的纯函数内核及测试。
- 后续：真实卡片运算、商店购买与点数、界面背包、日期、强制位移、股票和 AI。没有证据的条目保持 null/未启用，不编造统一效果。

## Core Gameplay

S2-02 接入后的预期流程：合法时机打开背包 → 选物品 → 选择合法目标或取消 → 提交时重新校验 → 原子地消耗物品并应用领域操作 → 记录效果事件 → 回到原阶段。持续效果由显式边界推进，不随动画帧或浏览器时间扣减。

## Screen Structure

本轮保留现有地图、决策侧栏、工具栏和结果页。S2-02 再增加背包入口、目标选择和取消按钮、效果/剩余时长提示；等待目标时阻止掷骰与轮换。未启用条目不出现可点击使用按钮。

## Interaction Flow

1. 宿主 GameEngine 验证 commandId、gameId、expectedRevision、当前操作者与暂停/终局。
2. 内核验证物品存在、已注册实施定义、数量及允许时机，生成唯一 decisionId；选择阶段不扣物品。
3. 取消清除 pending；确认重新校验目标存活、对象存在、时机、物品和冲突。
4. 返回新效果状态及事件/领域操作意图；宿主在同一草稿中执行具体领域运算，失败时整体不提交。
5. 宿主提交命令后，才让界面更新。到期/破产清理也是宿主边界处理的一部分。

## States And Feedback

空背包、未知物品、未注册效果、错误时机和无效目标返回明确拒绝原因。暂停冻结选择和边界；取消不消耗。相同 decisionId 不可再次确认。目标破产时移除以该目标为对象的持续效果；来源玩家破产后保留或清除由定义显式声明。终局由宿主停止所有新命令。

## Rules And Edge Cases

内核的 reject/replace/stack 是可选冲突策略，不代表任何原版卡片默认采用某个策略。冲突键按“组 + 目标”匹配，优先级只用于稳定排序（低值先执行，同值按创建序号）；尚未核实的反制链不能套用默认顺序。持续时长必须明确 clock（全局/来源/目标）、边界（turnStart/turnEnd/dayStart）和正整数次数；原版“天”不能换成全局回合。边界使用宿主单调序号去重，先清除失效对象再计时；应用效果本身不扣一次时长。

## Data And Technical Notes

`effects.ts` 是不持有计时器、不抽随机数、不改变现金/地产/移动的纯状态转换内核；输入上下文来自宿主状态，不能由 UI 或导入回放提供可信快照。内部只拥有库存、选择及效果实例。具体效果返回符号化 intent，领域处理器在 GameEngine 草稿上解释；内核成功本身不等于整个游戏交易已成功。

本轮不改 GameEngine 的三种 rulesId、不改变现有状态/回放 v1，也不往默认对局注入库存。S2-02 接入第一项实际效果时新增规则 profile，将 effects 子状态、目录/处理器版本指纹纳入该 profile；旧 profile 保持旧转换。回放仍只记录用户命令和确定性引擎事件，宿主重新派生上下文。内核测试通过 JSON 序列化的操作轨迹证明确定性，不冒称已新增正式游戏回放格式。

## Delivery Slices

- MVP / S2-01：证据清单、纯内核、确定性生命周期与失败原子性测试，S1 回归。
- Polish / S2-02：先完成有明确核验范围的一项卡片和获取渠道，接入新 profile、宿主原子交易和背包/目标 UI，再逐项扩展。
- Optional Enhancements：效果检查器和开发场景编辑器；不加入玩家正常流程。
