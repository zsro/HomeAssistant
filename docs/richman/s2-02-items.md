## 交付与规则登记

默认新场景为“道具对局（遥控骰子，候选规则）”：开局持有 → 选择 1–6 → 确认消耗并移动 → 点数格奖励 → 三越百货补购 → 再次使用。取消不消耗，暂停冻结选择；点数与现金/存款分开。旧地产、仅移动、自由验证模式仍可选。

来源沿用 `mytbk/rich4` 固定提交 `ec7d70e693059d1e781d9d1cc2ad7f36d360d39e`，路径、SHA-256 和固定版本链接在 [来源清单](s2-02-sources.json)。`effects-audit.json` 保持 S2-01 的历史审计快照，其中 enabled=false 不是当前游戏的启用清单；本批启用状态以本表和 items.ts 为准。本地字节仍来自 S1/S2-01 已审计文件，未改原安装目录或素材。A 表示本地数据事实，B 表示跨版本参考语义，不能据此宣称与本地原版运行完全一致。

## 接入与兼容

- 新规则 ID：`japan-tools-candidate-v1`。旧 `japan-turns-prototype-v1`、`japan-property-candidate-v1`、`japan-finance-candidate-v1` 保留原有语义、回放和随机序列。
- 状态/回放容器仍 v1；仅新 profile 增加 `items`（点数、供应、指纹）、`effects`（背包、选择）和回放 `itemFingerprint`。指纹包含规则参数、处理器版本、地图点数/商店配置和效果 registry；缺失或不匹配明确拒绝。
- GameEngine 是唯一写入者。校验命令身份/游戏 ID/revision、当前阶段、选择 token、目标和点数后，才原子提交效果草稿、消费、池回补及启动移动。普通掷骰在选择中被拒绝，指定点数不预先扣物品。
- `GameSession` 继续只管动画插值和界面投影；UI 不改库存。库存/点数使用阵容 player ID，非连续角色阵容也正确。
- 当前只接入即时效果，以及破产生命周期清理；回合/日期边界仍未接到持续效果，后续实现持续卡前必须补齐。未把 effects 测试定义开放给玩家。
- 新地图事件目录用 `build_item_nodes.py` 从既有审计生成；未修改 110 个道路节点、住宅资源或 379 帧素材清单。加载源哈希检查沿用原有能力。
