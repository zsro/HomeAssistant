日期：2026-10-02。在 S1-01～S1-03 未提交工作区上继续；没有重置已有成果，没有修改原安装目录、素材、审计数值或数据库。

## 交付与限定玩法

默认地产模式升级到 `japan-finance-candidate-v1`：日本地图银行存取款、途中银行后恢复移动、租金不足清算、破产退出、有效玩家轮换、最后存活者胜负面板，以及新流程的确定性回放。开局选择和页面说明均标注候选规则。

本阶段只开放无贷款、无利息、物价固定 1 的基础人类对局。租金不足时不把地产当成现金、不提供未经核实的抵押/卖地救济。确认清算后支付全部现有现金和存款，未偿金额记录在事件中，玩家破产；其地产变成无主待售，保留建筑等级。收款方只得到实付资金，收进存款，不得到地产。

破产后随机拍卖、股票/道具处置、银行贷款、神仙影响、日历结息、期限/目标资产胜负仍未开放。原版的破产拍卖分支已找到，本版暂不执行，属于明确的实现范围限制，不能宣称原版完整破产流程已经复刻。

## 命令与状态

- 状态/回放容器仍为 schema/version 1，通过新 rulesId 区分行为。`japan-turns-prototype-v1` 与 `japan-property-candidate-v1` 的回放仍使用旧规则，不插入银行、债务或破产决策。
- 新 profile 增加 `finance: { eliminated, winnerId, round }`；经济余额与地产继续属于 GameEngine。阵容和 `player-N` ID 稳定，退出只记在 eliminated 中。
- 银行阶段 `bank`，pending 保存 decisionId、节点和 passing/landing。`bank` 命令带 deposit/withdraw 和整数 amount；成功后消耗旧 decisionId，生成新 token。重复 commandId、过期 revision 和旧 token 均不能重复转账。`leaveBank` 调回原有移动后续流程。
- 每次最终落点先计算租金。足额沿用 property 确认；不足则直接发 `debtOffered`，pending 保存金额、租金分项、收款人、可付额和差额，尚不改变资产。
- `settleDebt` 在同一状态转换中支付全部流动资金、记录 `debtSettled` 的 due/amount/unpaid/paid、释放地产、记录 bankrupt；仅剩一人时进入 finished 并发唯一 `gameEnded`。
- debt 不允许跳过、借用银行动作、提交动画完成或结束回合。暂停期间不能转账或清算。finished 拒绝所有引擎命令；视角、全屏、下载回放与开启新局仍可用。
- 打开新建弹窗/重开前可暂停，取消恢复当前决策；确认新局生成新 gameId，旧银行/债务 token 无效。
- 银行/债务页面不改变引擎金额。银行表单根据 token 重建，成功后清空输入，避免保留上次金额再次提交。
