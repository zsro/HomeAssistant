# S1-03 地产闭环

日期：2026-10-02。基于 `f3e12f0` 及尚未提交的 S1-01/S1-02 工作区继续。此记录描述已实现的限定体验，不代表与用户本地原版的全部经济行为一致。

## 交付范围

默认进入 2–4 人地产体验：现金/存款、49 块普通地产的购买、0–5 级建筑、基础租金、地产归属与明细、暂停和重开、经济回放。新建对局可选六档初始资金（默认每人 100,000）、角色和种子；保留原来的“仅移动”和“自由验证”。

5 块大型用地的每两路格共享一个独立地产状态；专属建筑暂未开放，不使用普通住宅的升级或租金公式。6 家公司继续作为特殊节点，留给后续股票/公司系统。没有新增数据库表、存档、AI、日期或胜负。

资金不足以付租时保留完整待付决策和双方余额，不进行部分转账、不产生负余额、不允许跳过租金/结束回合，也不假装破产。界面说明该局需要新建或重开；S1-04 必须替换这个临时边界。

## 状态、命令与回放

- `game/economy.ts` 定义规则 profile、金额分摊、租金明细和数据校验；金额采用非负整数。
- `game/japan-properties.json` 是由 `scripts/richman/build_properties.py` 从审计数据生成的轻量运行目录。原始审计 JSON 不作为网页运行依赖。保留原始方向字段及来源哈希。
- `GameState.economy` 包含余额表、独立地产归属/等级和目录指纹；旧仅移动 profile 没有该字段。定义和状态分开，多个路格绝不复制地产状态。
- 路过只发 `nodeEntered`；最后一步 `landed` 后产生 `propertyOffered`，phase=`property`。动画 tick/animationDone 不能越过地产决策。
- `property` 命令带活跃 decisionId 和 accept；统一验证 gameId、revision、playerId、重复 commandId、暂停和阶段。成功一次性修改余额和归属/等级，发 `propertySettled`（含金额、支付分摊、收款方、最终等级）或 `propertySkipped`，随后才进入 turnEnd。
- 租金不可拒绝；购买/升级可拒绝。无效命令不消耗随机数、不写成功日志、不扣钱。React 传入当时显示的 decisionId，防止旧按钮作用于新决策。
- 回放容器及状态 schema 仍为 1，增加新的 rulesId、可选资金配置和目录指纹；经济规则/地图/目录不匹配时拒绝重放。旧 `japan-turns-prototype-v1` 仍可重建，仅移动的状态结构和事件未改。
- 回放为调试记录，页面只下载，不提供导入/存档功能；指纹用于兼容性检测，不是安全签名。

## 界面和素材

地产面板置于侧栏顶部，显示地名+独立编号、归属、等级、价格、现金/存款、付款分摊及同名租金明细。当前玩家的地产列表可展开。每位参与角色显示两类余额；地图按业主颜色标记，显示业主姓名和等级。

移除 49 个随机样例住宅，只保留 12 个原有地标；40 帧住宅随状态显示。资产生成量从 344 帧变为 379 帧，当前约 3.30 MiB，生成文件仍被 Git 忽略。旧素材需要重跑转换器。清单新增 `propertyArtVersion: 1`；启动核对 MapDat 来源、地产道路 kind 与住宅帧，错误时提示重新生成并可重试。

人物方向、相机、全屏、暂停弹窗、旧模式和退出清理保留。全屏侧栏可独立滚动，手机可滚动到购买/升级/租金操作。
