# S3-02b：免费/嫁祸租金反应与实际付款风险

本批新增宿主策略 `rent-v1`，继承 `tools-v1` 的遥控骰子/机器工人行为，单独保留 `basic-v1` 与 `tools-v1`。游戏引擎与规则保持 `japan-events-candidate-v44 / f9dbb7e9`。S3-02b 首组候选已实现并验收；S3-02 尚未整体完成。

## 设计与入口

新局仍默认全人类及基础策略；电脑策略可选“租金：免费与嫁祸反应（含道具）”。同局电脑共用一个版本，配置与回放 control 保存该版本，不写入世界快照或 GameConfig。不改变旧策略默认、不新增游戏规则版本。

只在既有租金反应窗口决策，不主动发起攻击、同盟或股票交易。原窗口先于必要清股：金额达到2000×物价或现金加银行不足时，先免费（旅馆除外）再嫁祸。电脑按窗口的 responderId 应答，不能用当前行动者代替实际付款人。反应后无第二次递归反制，后续付款/清股/破产均由现有 v44 引擎执行。

免费卡适用且金额为正时使用，避免付款及必要清股；若已无卡、不适用或无对外付款则拒绝并保留卡片。嫁祸重新核对库存、窗口 targets、玩家存在且未退出，优先选合法收租业主：原规则是业主本人付款免除转账，旅馆停留仍沿原逻辑。不预先挪钱、卖股或推测反应后的新闻。

业主不在合法目标集合时，按公开现金、银行及每股当前报价估算：逐股票 `trunc(股数×报价/100)`，不把地产、贷款额度、未到账分红或退出后公共处置所得当成可支付资金。排序依次为非同盟、较小资产不足额、不需清股、较高流动资金、座位顺序。同盟只有自己连持股也不足时才作为最后备选；没有合适目标则拒绝嫁祸。当前普通租金窗口通常包含业主，因此这个备用分支主要是领域边界证据，不伪称原图实际出现。

实际付款人即使是非当前座位，也由 Session 现有归属规则控制：人类付款人等待人类，电脑付款人确认付款或债务。必要清股在引擎选择付款人后发生，策略只解释风险；不足则退出。发生退出强拍时，所得进入公共资金，不能救活玩家，也不能补足原债。

商店优先补一张免费（25点）、再一张嫁祸（40点）；必须库存为零、卡包未满15、真实有限货架有该项、供应及点数足够。购买后新窗口再算，因此不会重复买同一种卡或挤掉已有卡。之后仍委托旧道具策略补遥控骰子或离店；没有更改旧tools-v1的商店优先级。
