# S1-02 对局引擎与回合接入

日期：2026-10-02。在 `f3e12f0` 及尚未提交的 S1-01 工作区基础上继续；保留全部 S1-01 工具和审计资料。

## 1. Goal

为日本地图建立单一对局状态，使 2–4 位本地玩家按顺序行动，移动与决策可以按记录确定性重放，同时保留原有画面、人物方向、岔路、暂停、全屏及场景清理。

## 2. Scope

已实现：纯 TypeScript 引擎、固定顺序轮换、种子随机数、命令校验、分段移动确认、事件日志、回放导出及代码重放入口、新建对局和隔离的自由验证模式。

本轮没有实现：资产、地产结算、银行、AI、游戏日期、胜负、云端存档和网页导入回放。候选经济数据尚未接入运行规则；不创建金额为零的假资产，也不推导原版利率。

## 3. Core Gameplay

进入页面默认四人轮流模式。通过“新建对局”选择 2–4 个角色、可选种子，按列表顺序开始行动。每回合掷一次骰子，逐段走完点数，途中选择岔路，停下后点击“下一位”移交操作。全部玩家各行动一次后进入下一轮。

轮流模式禁用任意切换操作者和定位岔路。需要检查素材或路线时，新建“自由验证”模式，仍使用原 `Traversal` 及四角色手动切换。本轮不把固定顺序、初始路格或单骰规则宣称为完全核实的原版行为。

## 4. Screen Structure

- 工具栏：当前轮次/回合、新建对局、全屏。
- 地图和操作条：沿用原画布与视角控制；回合完成后将掷骰按钮替换为“下一位”。
- 角色侧栏：仅显示参局角色，突出当前操作者；轮流模式下不能点击换人。
- 旅途记录：当前决策提示、路格、累计移动和最近回合记录。
- 新建弹窗：模式、角色、种子、取消/开始；无效人数提示，不替换当前对局。
- 验证工具：种子、状态版本、道路显示、受模式限制的岔路定位、回放 JSON 下载。

## 5. Interaction Flow

1. 读取素材并创建 `GameSession`，默认进入四人轮流模式。
2. `GameEngine` 接收掷骰命令，只在合法阶段推进随机源并锁定点数。
3. 场景适配层播放骰子动画，以 pending token 确认完成。
4. 引擎根据存储的道路边发出路段或岔路决策；选择岔路不扣步数。
5. `GameSession` 只插值坐标。整段播放完成后提交带 token 的确认，引擎才更新路格和剩余步数。
6. 每次到格产生 `nodeEntered`，最后一步额外产生 `landed`；当前阶段仅记录，不计算经济事件。
7. 停在 `turnEnd` 等待“下一位”，确认后轮换。不能在这个阶段再次掷骰。
8. 重置保留模式、角色和种子，但创建新的 gameId，清空日志、插值与进度；新建对局可更换配置。

## 6. States And Feedback

引擎 phase：`idle → rolling → choosing/moving → turnEnd → idle`。暂停为独立布尔状态，保留正在播放的 token 与插值进度；暂停期间拒绝除恢复以外的推进命令。

窗口缩放、全屏、相机和动画帧仅属于显示状态，不产生对局命令。打开新建或重置弹窗暂停当前对局，取消恢复原暂停状态；确认创建新局后旧动画不能推进新局。

角色少于两位时显示错误；加载失败重试与原型一致。离开页面仍释放资源和动画回调。刷新页面不保留对局，页面已有提示。

## 7. Rules And Edge Cases

| 规则 | 当前处理 | 证据状态 |
|---|---|---|
| R03 单骰 | 均匀 1–6；带版本的伪随机源和拒绝采样 | 工程原型规则，非原版 RNG 复刻 |
| R03 道路 | 原 110 节点；排除上一格，死路允许折返；仅走已存储的有向边 | 邻接数据已核验，完整原版移动语义仍待核验 |
| R03 事件 | 到格与落点分开记录，为 S1-03/S1-04 保留结算入口 | 未执行银行/商店/神仙等效果 |
| R06 回合 | 2–4 人按所选列表固定轮换；明确确认交给下一位 | 本轮确定的体验规则，不等同原版顺序算法 |
| 初始位置 | 依参局顺序使用地图数组前 N 个节点 | 沿用验证方式，未声称原版出生位置 |
| R04/R05 经济 | 能力开关为 false，初始资金/利息/胜负为 null | 继续保持未知与禁用，待 S1-03/S1-04 |

命令必须满足 gameId、唯一 commandId、expectedRevision、当前 playerId、阶段及决策 token。重复、过期、其他玩家、其他对局或非法目标都被拒绝，拒绝时不更新状态、随机源或成功日志。

动画完成不是时间验证：纯引擎不依赖墙钟，测试或未来无动画运行器可直接确认同一 token。浏览器适配层负责播放时长。这是本地逻辑约束，不是联网反作弊方案。

引擎权威状态只含当前离散路格与决策，不含坐标插值、PixiJS 对象和计时器。`state`、`events` 及导出记录返回复制数据，避免调用方修改引擎内部状态。自由验证与回合模式互相替换，一个场景不会同时运行两套移动规则。

规则 ID 为 `japan-turns-prototype-v1`，状态/回放格式版本为 1。种子先 trim，长度不超过 64 字符；相同地图、配置、种子、操作序列可重建相同状态和事件顺序。回放包含初始配置及所有成功命令，地图指纹用于版本兼容检测，不作安全校验。地图内容或规则版本不匹配时拒绝重放。

使用方式：

```ts
import { replayGame } from './game/engine';
// replay 是下载的 JSON 对象；nodes 为同版 manifest.map.nodes。
const restored = replayGame(nodes, replay);
const state = restored.state;
const events = restored.events;
```

这是开发者入口，尚无网页上传功能。事件日志只存在当前页面内存，与数据库模式无关。没有新增数据库表、网络对局接口或登录绕过。
