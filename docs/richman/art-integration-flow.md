## 3. Core Gameplay

本轮只读现有 `SessionSnapshot`，不发出命令、不消费随机数、不修改状态时钟或回放指纹。角色仍由游戏规则确定位置、朝向和状态；动画每帧只选择图片。路障/危险物的放置、携带、爆炸和清除继续使用已有规则。

## 4. Screen Structure

地图图层：底图 → 常驻道路 → 道路图块 → 按深度排列的建筑/人物/地面道具 → 路线预览与选择反馈。人物和道具使用原图锚点，且同步像素点选遮挡。骰子使用 DOM 图片，图片失败时回退符号/数值。现有商店、背包、事件和小游戏 Web 面板保持可用。

## 5. Interaction Flow

每项资源按以下顺序推进，任何证据缺口都记录后转入暂缓，不阻塞其他项目：

1. **登记**：记录缺图位置、Web 状态字段、原文件哈希、资源编号、帧数、方向与锚点。
2. **核对**：解包联系表，核实图片含义；参考反汇编只作为索引/行为线索，不跨版本照抄绝对编号。
3. **判定**：现有状态足够驱动 → 接入；需要未知格式、专属输入或时间线 → 暂缓，写清恢复条件。
4. **导出**：离线转换并保留透明索引、原始锚点；图集不超过 4096×4096，否则拆分。输出版本和审计哈希。
5. **适配**：用纯展示函数选择姿态。缺失时回退既有图标/步行形象，不新增游戏事件。
6. **验收**：检查全部方向、静止/移动、状态优先级、暂停、恢复、换座位、退出清理；浏览器检查桌面及 390px 截图。
7. **打包**：更新 `release-assets.json`，本地 `npm run release:frontend`、`npm run release:verify`；部署按根 `AGENTS.md` 的提交、推送、服务器同步、部署顺序执行。

## 6. States And Feedback

- 姿态优先级采用 Web 展示约定：监禁 → 住院 → 冬眠 → 梦游 → 有效工程车 → 当前车辆 → 步行。保留原始到期标记 `128`，等规则真正清除才恢复。
- 选用人物索引前先通过 `participants` 找座位，支持非连续人物组合；工程车暂停时不会盖过梦游。
- 暂停冻结现有动画计时。重新开始、清除物件、离场立即移除对应精灵，销毁场景释放纹理。
- 携带炸弹跟随人物实时插值；消失、出国、住院、入狱、入住酒店时隐藏。地面道具使用原版第 0 朝向；炸弹携带高度沿用 Web 的 45 像素偏移。这里未声称复现原版专属携带偏移。

## 7. Rules And Edge Cases

- 不以事件编号替代绘图编号，不把光标小图当成背包道具图。`Data.mkf[0]` 是 43 帧光标/工具指示图；`Panel.mkf[25]` 包含对话和人物表情，均不能按库存序号直接映射。
- SPR 的透明依据是**调色板索引 0**，并非所有 RGB 黑色；本批修正该解码问题并增加回归测试。
- 素材缺失或姿态版本不支持时保留步行人物；已有回放仍按原规则执行。骰子总点数 7–18 不错误映射为单骰图片。
- 原版帧的锚点可以在图外，不能截断或替换为几何中心。图集重新排列后，所有矩形和点选 mask 从同一清单获取。

## 9. Delivery Slices

第一批静态地图和建筑已完成；第二批本次完成车辆、状态、道路道具和骰子。后续暂缓项按以下条件恢复：

| 批次 | 恢复条件 | 验收门槛 |
| --- | --- | --- |
| 卡片/道具图片 | 每个库存 ID 有确定的原资源/帧映射；未知资源格式先补解码 | 全量 ID 覆盖、无误图、移动端可读及键盘可操作 |
| 短时演出 | 明确使用事件、开始/结束、暂停/重置/回放中断协议 | 不重复结算、不改变 RNG、不留下旧队列 |
| 小游戏皮肤 | 逐游戏核对坐标、碰撞、帧时钟与输入，完成一项再推广 | 原有确定性回放通过，手机布局和操作可用 |
| 完整窗口/对话 | 选定可响应式拆分的原版元素，明确各状态/表情触发 | 保留网页焦点、触屏热区和阅读顺序 |
| 所有者调色 | 从原文件验证颜色索引范围与所有者映射，导出索引 mask | 建筑非产权区域不被误染，所有玩家及无主状态正确 |

若条件仍不满足，继续保留 Web 展示并更新本表，不用占位图假装已完成移植。
