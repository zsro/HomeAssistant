## 验收口径

状态：**本计划 Web 必做界面及本地发布准备完成，未部署**。

本次验收的是当前 Web 已有功能在原版风格界面中的完整入口、操作和发布完整性。原版素材、静态代码证据与 Web 运行截图分别记录，不把素材组合图当成原版运行截图。未运行 Windows 原版，因此不宣称像素级、所有原生业务或演出 100% 复原。

原版主体布局、工具顺序、GO、资料页、菜单和已核实窗口素材已接入。未知素材映射与尚未实现业务集中列于 [暂缓与差异清单](ui08-deferred.md)，继续按“保留入口、明确提示、业务挂起”处理。

## 本轮调整

- 更新 UI-01～UI-04 浏览器脚本：进入新主菜单、展开高级开局设置、使用单实例窗口、操作暂停/退出确认。桌面仍逐项断言原版四区坐标；紧凑布局断言地图逻辑尺寸和无横向溢出，不再要求手机复用桌面坐标。
- UI-01 专注布局与入口，UI-02 专注原掩码、GO 拖动、资料、小地图及真实掷骰；重复的机器工人流程集中到 UI-03，透明像素/建筑命中继续由地图测试覆盖。UI-03 保留真实地图选择、全屏/手机/暂停恢复、防重入、必答窗口和下载回放验证。
- 新增 `classic-acceptance-browser.cjs`：DPR 2、29 个目录入口、169 个发布资源、真实电脑回合、故障恢复及资源清理。
- 新增 `classic-performance-browser.cjs`：同一 Chrome、相同窗口、交替运行改造前已提交发布包与当前发布包，分别记录加载和帧率。性能数字只代表本机 headless/SwiftShader 验证环境。

本轮没有改动游戏规则、经济公式、AI 策略或数据库。系统菜单的暂停/继续会产生真实 pause 命令和状态版本变化，测试据此校验，不再误认“打开任何窗口都不能改变 revision”。普通资料/库存浏览仍不提交业务命令。

## 浏览器与异常验收

开发页面跑通 UI-01～UI-06 及 UI-08 专项；UI-07 完整流程、UI-04 首段购地/银行、UI-05 股票/库存、UI-06 认输/处置和 UI-08 专项均在正式 `release/frontend/` 上再跑。UI-04 开发长路线仅加速已有动画 tick，不注入经济或地图状态；生产包用原速跑 21 个界面动作。稀有业务使用独立展示夹具验证回调，明确与真实路线区分。

| 检查 | 结果 / 边界 |
| --- | --- |
| 六种尺寸 | 640×480、1280×960、1440×900、1440×1080、844×390、390×844 无页面横向溢出；小屏允许纵向滚动 |
| 逻辑四区与全屏 | 桌面按 640×480 四区坐标校验；原生及 fallback 全屏、旋转保留同一场景 |
| 高 DPI | DPR 2 的逻辑地图 440×440、真实 canvas 880×880；重复真实地图目标选择、全屏/手机恢复和回放 |
| 资源完整 | 浏览器逐项请求 169 个白名单文件，图片实际解码，最大单张纹理不超过 4096×4096；完整包另校验哈希 |
| 加载失败 | 必需 manifest 404 显示错误、无 canvas，撤销故障后重试成功 |
| 可选图片异常 | 动画 manifest 缺失/损坏、菜单图片缺失均不阻断真实掷骰；图片缺失并不计为视觉通过，正式包完整性检查不允许缺图 |
| 音频缺失 | 控件明确提示暂不可用，游戏可继续 |
| 中途退出 | 素材请求尚未完成时退出，晚到响应不重建场景 |
| WebGL 丢失 | 使用浏览器扩展真正丢失上下文，显示重试，重新加载后可掷骰 |
| 清理 | 正常、失败/重试、晚到响应和上下文丢失后退出，canvas、待执行 RAF、ResizeObserver 与被监测的场景/全局监听器回到进入前基线（均为 0） |

监听器探针覆盖 canvas 及 window/document 的 resize、visibilitychange、fullscreenchange、keydown；不宣称对浏览器内部所有监听器做了堆内存证明。测试鉴权仅用于本地，不请求生产数据库。

## 自动测试、性能与发布包

性能对照使用同一台机器的 Chrome headless + SwiftShader、1440×1080 / DPR 1，每版三次新上下文，交替顺序，场景静止时每次采样六秒；全量测试同时运行，数值用于粗略回归观察，不能替代移动设备或真实 GPU 基准。

| 中位数 | 改造前已提交包 | 当前发布包 |
| --- | --- | --- |
| 路由进入至 canvas 就绪 | 896 ms | 884 ms |
| 场景自身加载 | 255 ms | 181 ms |
| 帧率 | 59 FPS | 59 FPS |
| 请求数 | 22 | 77 |
| 浏览器记录传输量 | 7,712,223 字节 | 8,900,997 字节 |

没有观察到明显加载或帧率退化。新增菜单、工具和窗口图使请求增加 55 个、传输增加约 1.19 MB；两个版本的地图实际画布尺寸不同（1090×626 与 440×440），因此不能把场景加载下降解释为同等渲染工作量下的优化。素材已按当前场景/决策显示条件加载，未将全部审计帧放入运行包。完整样本见 [性能数据](ui08/performance/results.json)。

生产包另外使用 `hasTouch/isMobile` 的手机上下文，通过真实 tap 操作主菜单、设置与 GO，验证不依赖 hover，随后清理回到零。见 [触摸结果](ui08/built/touch/results.json)。

完整测试按两段执行：先完成 14 个较慢文件，再排除已完成文件继续剩余测试。后段使用仓库现有 `RICHMAN_SKIP_REPEATED_PREFIXES=1`，仅研究/综合策略两个验证器省略重复的逐前缀整局重算；8 份对应回放首先核对归档 SHA-256 一致，完整逐命令验证、最终状态/事件哈希、归档摘要与其他回放矩阵仍执行。没有修改测试或验收阈值来使结果通过。[归档匹配记录](ui08/prefix-archive-check.json)与分段日志保留，不能据此声称本轮重新计算了这两组的全部重复前缀。

最终按文件去重合计 **188 个测试文件、2685 项用例通过**。首段 14 文件 / 64 项通过，后段 174 文件 / 2621 项中一项旧文案断言失败：UI-04 已把“候选规则 · 物价 ×3”简化为“物价 ×3”。本轮将断言限定在“地产与资产”区域内检查原有物价数值；规则版本与费用范围断言保留，修复后该文件 4 项全部通过。保存初始失败日志与复测日志，不把复测重复计入总数。

Lint、TypeScript/Vite 构建、8 项导出测试、1 项发布校验器测试及发布包校验通过。验证包括 44 规则版本 × 2/3/4 人的 132 组兼容矩阵、已有黄金回放、各策略长局与 UI 组件测试。仅测试断言改动后重新打包，核对新旧运行文件列表/哈希完全一致，源码指纹更新；已跑过的生产包浏览器结论仍适用于相同运行文件。见 [验证附件](ui08/README.md)。

发布流程本轮止于本地打包与校验。发布目录为 `release/frontend/`，清单为 `release/frontend-manifest.json`；共 191 个文件，其中大富翁白名单资源 169 个、UI 图片 124 张。联系表和审计用大图不进入游戏资源白名单。部署前如修改前端源码，必须重新打包。

本轮不提交、推送或部署。后续发布仍按根 `AGENTS.md`：检查→正常提交→推送 `origin main`→服务器干净检查和快进同步→分支/HEAD/干净状态一致→在 `/var/HomeAssistant` 执行部署→健康/Nginx/PM2/最终 Git 状态检查。


## 复跑入口

- 全部前端测试：`npm --prefix frontend test -- --maxWorkers=4`。默认包含耗时较长的重复前缀验证；使用归档优化选项前须先核对相应回放哈希，并在结果中标明边界。
- 素材导出测试：带 Pillow 的 Python 执行 `python3 -m unittest discover -s scripts/richman -p test_ui_export.py`。
- 代码与打包：`npm --prefix frontend run lint`、`npm run test:release`、`npm run release:frontend`、`npm run release:verify`。
- 浏览器：设置 `PLAYWRIGHT_MODULE` 为本机 Playwright 模块目录，运行 `scripts/richman/classic-{shell,turn,window,property-bank,business,event,system,acceptance}-browser.cjs`。通用参数 `RICHMAN_TEST_BASE_URL` 默认本地 5174，`RICHMAN_TEST_OUTPUT` 指定结果目录；UI-03 支持 `RICHMAN_TEST_DPR=2`。
- 生产包：以 Vite preview 的 `--outDir ../release/frontend` 提供本地 5175；设置 `RICHMAN_BUILT_SMOKE=1` 运行业务/事件/银行脚本。银行须用 `RICHMAN_UI04_PLAN` 指向本轮开发路线的 plan.json。系统和专项脚本可直接运行生产包，不导入开发模块。
- 性能：本地 5176 提供改造前已提交包，5175 提供当前发布包，运行 `classic-performance-browser.cjs`；结果必须同时记录渲染器、DPR、视口及画布尺寸。
